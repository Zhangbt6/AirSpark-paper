AirSpark paper figures · v0.21 · 2026-10-23

中文网页、英文稿同源，图件均为研究设计，不是实测结果。

图 1. AirSpark 模拟学院平台架构。视觉仿真、物理仿真与场景任务共同支撑任务执行、同步记录、监督生成、训练与评价工具。学生策略、采集专家和 SparkMentor 通过共享接口调用这些能力。图 2 进一步描述运行在学院设施上的策略自进化方法。

图 2. 反馈驱动的策略自进化方法。执行反馈 Eᵣ 引导能力诊断与主动采集；学院通过物理前缀、专家延续与质检产生数据，再训练并验收学生。学习反馈 Fᵣ 将任务表现变化、能力保留和成本写入跨轮记忆 Mᵣ。学习反馈通过多轮记忆支持有界方案修订 ηᵣ；固定、规则式、当前反馈与历史反馈决策共用学院执行器与验收规则。最终测试在闭环之外进行。

图 3. 先核验任务、初始策略与部署合同，再在至少两个任务中比较固定、规则式与 Agent 修订；至少一个主任务增加原生／学院数据来源对照。冻结学生后，原生回测与真实机器人执行分别报告。

图 A1. 视觉与物理执行细节。3DGS 提供静态场景外观，显式物理资产承担碰撞、接触与载荷；MuJoCo 状态驱动 UE 动态资产。适配器统一坐标、时间和动作语义，并区分学生输入、特权诊断与专家监督。

图 A2. RSI 经验生成步骤的展开。从合法初态实际执行前缀，在目标过程条件上采集专家延续；每条分支是独立的物理执行。前缀提供允许的历史上下文，动作监督仅来自通过质检的专家区间。轨迹为方法示意，非实测结果。

图 A3. 图 2 的反馈原理解释。学习状态 x 与能力测量 ĉ 分开，学习决策 μ 与机器人低层控制 K 分开。U 表示实际采集和训练，H 表示评价测量，未引入学习收益预测器。最终测试不进入反馈闭环。

Rebuild order (scripts/ and figures/ must be sibling folders):
1. python scripts/build-figures.py
2. python scripts/localize-figures.py
3. python scripts/build-feedback-figure.py
4. python scripts/build-study-figures-v021.py  (overrides figures 2 and 3)
5. node scripts/export-figures.cjs             (requires sharp)
Do not run steps 1/2 after step 4 without rebuilding step 4.
